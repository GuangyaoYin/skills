# 项目profile与参数归属

一个profile描述一个独立研究项目；数据、参数、结果和验收均属于该项目，不属于通用程序的全局默认值。当前工具接收**单个已展开JSON**，尚未实现自动层叠／合并profile的命令，不能假设配置会自动从案例或父目录继承。

配置从`assets/config/workflow.example.json`复制后填写。相对输入路径基于配置文件所在目录，不是运行时当前目录。原波形可以在其他磁盘；项目配置、元数据和输出清单应可追溯。

| 类别 | 示例字段 | 取值规则 |
|---|---|---|
| 必需项目输入 | 波形、台站、响应、初始模型、时间与坐标基准、时段／范围 | 用户提供或可靠元数据解析；解析结果应确认并冻结 |
| 软件约束 | 模型期望的采样率／通道、文件格式、后端最大容量 | 由固定版本的模型／软件声明；变更需重测 |
| 科学参数 | 搜索网格、震相／CC筛选、频带、权重、阻尼、震级方法、误差与精度门槛 | 项目证据及代表性试验选择；没有依据则未配置 |
| 派生值 | 走时表范围、深度层转换、参考点、绘图范围 | 记录输入、算法、值与来源哈希；不能默默借用某个地区 |
| 工程资源 | 并发、线程、内存、批大小、超时 | 小规模测量后按运行资源设置，不作为质量门槛 |
| 绘图主题 | 字号、DPI、图例、无图名备注、输出格式 | 可配置风格；显示范围不改变科学目录 |

未来配置解析应按显式顺序合并：后端格式约束 → 用户选定的项目profile → 本次显式覆盖，生成`resolved.json`。每个有效值标注`user/metadata/derived/pilot/backend_constraint`来源。案例目录不在继承链内；读取案例必须由命令或项目配置明确选用。

地区、时间、台站数量、事件数、仪器名、经验震级系数和深度范围不得写入核心代码。没有确认的值保持`null`并返回缺失项；工具不能用“上个项目”的配置完成预检。

案例中有效的参数只能成为该案例profile的证据，不能仅改路径后宣称适用于另一研究区。复用参数时仍需核验模型、台阵几何、频带、响应、距离和震级适用域。
