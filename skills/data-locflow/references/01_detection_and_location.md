# 通用检测、关联与定位流程

本文适用于任意研究区的连续波形地震目录构建。主链采用 PhaseNet → REAL → VELEST → ph2dt/hypoDD_dtct → FDTCC → hypoDD_dtcc；需要时可替换某个后端，但必须保持输入输出契约、时间与身份映射以及阶段验收。

**当前交付边界：** 本包提供流程规范、配置模板和管理检查工具。科学后端的通用适配、原始设备格式转换与真实异区全链运行仍需实施和验证。本文中的“应”描述目标契约，不表示这些计算已经自动实现。

## 1. 输入完整性

| 输入 | 必须明确的信息 | 使用阶段 |
| --- | --- | --- |
| 原始或已转换波形 | 文件格式、台网/台站/位置/通道、真实起止时刻、采样率、方向/极性、缺口和重复片段；保留原文件 | 拾取、相关、测幅 |
| 台站部署元数据 | 坐标、坐标基准、高程与单位、部署有效时段、台站唯一身份；通道方向和时钟修正记录 | 关联与所有定位 |
| 一维或后端支持的速度模型 | 层顶深度、Vp、Vs、单位、深度基准、适用范围和模型来源 | 走时、绝对与相对定位 |
| 拾取模型 | 固定版本的程序、权重、网络输入采样率与通道约定，以及完整模型文件的指纹 | 神经网络拾取 |
| 仪器响应与采集信息 | 每通道/时段响应、灵敏度、增益是否已移除、数据物理单位 | 物理幅值与震级；是否用于检测支路由项目策略决定 |
| 项目配置 | 研究范围、起止时间、原始时标、输出坐标与深度基准、阶段参数及验收规则 | 所有阶段 |

波形和速度模型不能替代台站坐标。响应元数据不一定是纯到时定位的程序输入，但物理振幅和震级不能缺少可追溯的响应、增益和单位约定。只有这些元数据已经可靠包含在输入包中时，才可能简化用户需要填写的路径。

目录采用通用 `magnitude` 与 `magnitude_type`；不同震级类型分别保留和统计，不默认为ML，旧列名只能通过显式映射兼容。

建议采用标准输入表；设备格式由适配器转换，禁止将文件名或站名前缀当作仪器类型、单位、坐标或时区的唯一依据。台站同名而台网不同、同一台站更换设备或移动位置，都应保留部署身份和有效时段。后端只能接收短站名时，应生成唯一别名并保存双向映射。

标准字段和单位见 [02 输入与目录契约](02_inputs_and_catalogue_contract.md)。

## 2. 阶段输入、输出与完成条件

| 阶段 | 输入 → 标准结果 | 完成条件 |
| --- | --- | --- |
| 波形整理 | 原始记录 → 波形索引、连续有效段、缺口/时钟/削波/分量质控 | 时标、采样率和通道一致性通过；任何补齐、重采样和时钟修正均留档 |
| PhaseNet 拾取 | 处理后的波形、模型权重 → P/S拾取表 | 每条到时含绝对时刻、概率、原波形及样本索引；所有输入任务完成或显式失败 |
| REAL 关联 | 拾取、台站、走时表 → 初始事件、事件—震相关系和关联质控 | 走时网格/索引正确，跨块关联和去重可查，不丢尚未完成的拾取任务 |
| 关联后质控 | 初始事件与相位 → 接受/拒绝事件及逐拾取状态 | 明确区别整事件筛除和逐拾取筛除；供定位的相位集必须与记录的方法一致 |
| VELEST 绝对定位 | 相位、台站、模型与控制文件 → 位置、原时、残差和拒绝清单 | 定位模式、模型和站改正策略明确，覆盖和残差验收通过 |
| ph2dt 配对 | 接受事件与拾取 → 目录差分到时、事件对和链接统计 | 每条观测及事件对可回溯，整数ID与全局UID可逆映射 |
| hypoDD_dtct | 目录差分到时、站表、模型 → 相对重定位结果 | 连通簇、迭代、异常深度、丢事件及拒绝原因可查 |
| FDTCC | 相关事件对、真实波形窗、相位与位置 → 互相关差分到时 | 时间差符号、频带、窗口、CC/SNR质量、批次完整性和全局合并通过验收 |
| hypoDD_dtcc | CC差分到时，按策略选用目录差分 → 最终相对位置 | 固定实际控制文件，验收收敛、网络、稳定性和异常值 |
| 目录整合 | 各阶段接受/拒绝、来源与质量 → 全事件及筛选视图 | 来源闭合、身份唯一、回退阶段明确，未知质量不被伪装为已通过 |

这条链不应依赖“绘图脚本顺便产生下一阶段科学输入”。质控、数据转换和绘图应形成独立产物及清单；缺少必须的质控结果时停止下游，而不是悄悄改读未筛选文件。

## 3. 参数怎样确定

没有足够证据时，科学参数应保持未设置或候选状态，在项目试运行后批准。软件自带默认值可以记录为候选来源，但不能自动成为研究区的科学默认值。所有有效值均记录类型、单位、来源、试验、适用范围、批准状态及输入/程序版本。

| 参数组 | 类型与单位 | 如何确定与必须试验的内容 |
| --- | --- | --- |
| 拾取采样率、通道和处理 | 频率、分量顺序、滤波参数、重采样/缺口策略 | 受固定网络权重的输入要求约束；验证重采样、抗混叠、方向、极性和不同噪声条件 |
| 拾取概率、峰间隔、窗口与重叠 | 无量纲概率、时间或样点数，必须声明单位 | 用独立人工标注样本评价漏检、误检和到时偏差；按仪器、信噪比和边缘窗口分层 |
| REAL 搜索域与步长 | 水平角度或距离、深度、时间 | 根据台阵几何、可检事件范围和走时误差设候选；检查分辨率与运行代价，不由行政边界直接决定 |
| REAL 关联门槛 | P/S/总相位/双相站数、残差窗、事件间隔 | 用真事件与噪声样本评价关联完整性、假事件及重复关联；保留不达标理由 |
| 走时表 | 距离/深度范围及间隔、排列和相位 | 从已批准模型生成；覆盖实际查询并与后端索引一致，禁止独立填写互相冲突的范围字符串 |
| VELEST 模式与筛选 | 模式枚举、距离、方位空缺、残差、最小观测、深度与阻尼 | 区分只定位与联合模型/站改正反演；检查残差、几何覆盖、模型敏感性和独立事件 |
| ph2dt 配对 | 距离/分离、近邻数、公共相位、观测权重与每对上下限 | 根据事件密度和观测误差试验链接覆盖、连通性与计算容量，不以保留率单独选值 |
| FDTCC | P/S窗、频带、采样间隔、移位、CC与SNR门槛 | 用已知时移波形和人工抽检验证；不同仪器/距离/信噪比须覆盖，不因CC较高就忽略错误相位 |
| hypoDD 迭代 | 数据类型、P/S权重、异常值/距离重加权、阻尼、求解器、簇选择 | 版本化完整迭代组并读取实际有效值；用网络与模型/权重扰动评价稳定性 |
| 回退与精度门槛 | 阶段枚举、质量条件、稳定性与误差门槛 | 按研究所需分辨能力事先定义；不能把运行成功或簇更紧当作精度达标 |

这里不指定通用阈值、固定深度范围、固定Vp/Vs或统一经验公式。震级和不确定性的参数选择见 [03 震级与定位误差](03_magnitude_and_uncertainty.md)。

**资源参数单独管理：** 工作进程、线程、内存预算、I/O并发、任务批大小、超时和重试次数由机器及运行测量确定。事件对分批应改变计算调度而不改变科学输入集合；这种等价性必须经工程测试。改变候选事件、配对规则、窗口、滤波或质量阈值属于科学参数变化，不能伪装成资源优化。

## 4. 模型、走时表及后端转换

保留一个有来源的标准模型，再为各后端生成原生输入。后端只支持常数Vp/Vs、不能表达速度梯度或有特殊深度约定时，应保存转换/简化规则并做敏感性试验；不要假称所有阶段使用完全相同的模型，也不要将位置校准结果静默覆盖为新模型。

每次计算至少检查：

- 原模型、生成表、控制文件和实际执行文件的指纹及版本相互对应；更换任何一项使相关缓存失效。
- 深度正方向、零点与台站高程单位一致。是否考虑高程、浅层外推和台站改正由明确的后端策略决定。
- 层数与层顶/速度数组长度严格相等，层顶有序、速度有限且符合模型物理约束；禁止依赖程序静默忽略尾层。
- 表中每个节点及排列符合声明，检查重复/缺失节点、深度和距离步长、所有数值及相位列；行数相同不代表网格正确。
- 实际事件—台站查询处于表内，插值和端点规则已验证；不能仅检查事件位置是否在研究区内。

当前 `check-travel-table` 的原生契约是深度优先排列、距离从一个正步长起，10列依次为距离、深度、P/S走时、P/S射线参数、P/S垂向慢度、P/p和S/s相位名；前8列必须是有效数字。其他后端格式应显式转换，不能强行当作该格式读入。该结构约定不是走时生成或定位已经通过科学验证的证明。

## 5. 时间、跨日与身份映射

以完整绝对时刻作中间层：

```text
pick_time = trace_start_time + sample_index / actual_sampling_rate
relative_arrival = pick_time - chosen_event_origin
```

输入时区、时钟误差和修正记录必须明确；输出UTC时保留原始时标及转换来源。不能根据文件名猜时区，不能为“看起来匹配”静默平移时间。P/S必须使用同一时基；滤波、重采样、分块和模型内部偏移均需检查是否改变样点到时间的映射。

如果后端接收“日期＋当天秒数”，从完整绝对到时推导日期与秒数，处理跨午夜、月末、年末及带偏移时区。不能仅对秒数取模，也不能从记录文件名取日期后只叠加样点秒数。相邻块应有经试验的重叠和关联/去重策略；逐日调度本身不保证跨日事件完整。

互相关波形窗也可能跨越文件或日期边界，应验证所有实际样点、片段拼接、缺口及部署时段。文件存在或头信息有效，不能替代窗内信号有效性的检查。

每次后端重编号都保留 `source_record/pick_uid/event_uid ↔ backend_id` 映射；日内编号不能直接当成全项目主键。更新初始化位置或原时后，若相对到时参考发生改变，必须同步调整到时，使原始绝对观测保持不变。差分到时交换事件顺序时的符号、原时修正项和权重含义必须通过已知样例验证。

## 6. 绝对位置、相对精度与回退

绝对定位依赖到时、台站坐标及速度模型；相对重定位用共同路径的差分约束改善事件间位置关系。相对簇变紧、数值残差减小或求解器返回位置，都不足以证明绝对位置准确。应分别报告观测重复性、模型/台站敏感性和有独立基准支持的绝对误差。

逐阶段数量变化需要区分两类原因：

- **科学性筛除：** 相位/台站覆盖不足、残差或深度异常、配对不足、CC/SNR不合格、网络断连、迭代异常值等。
- **接口或运行失败：** 缺分量、台站漏配、时标错误、未完成拆分、容量截断、错误目录布局、批次遗漏、版本不兼容、错ID或解析失败。

先排除接口/运行失败，再考虑调整科学阈值。验收同时记录输入、接受、科学拒绝、运行失败和待处理，数量必须闭合；不把所有丢失都写成“低质量”。

可在完整目录中保留最后一个已通过验收的较早阶段位置，但明确最终阶段、回退原因和质量。不能将绝对定位、目录双差和互相关双差的事件全部标成同一种精度；不能将未完成定位或未验收的初始解自动升格为正式结果。

## 7. 任务隔离、恢复与迁移验收

科学程序在独立任务目录执行，原始输入保持只读。转换、质控、配对、分批与目录发布分别形成可解析产物；子进程必须检查退出码，所有上游任务完成并验收后才启动依赖阶段。不能用文件存在、部分非空结果或旧完成标志代表阶段成功；合法的空结果也应有明确状态。

缓存键至少包括输入及模型指纹、解析后的科学参数、程序/权重版本和适配器版本。执行资源调整是否影响结果需经过测试；旧批次只能在输入与分批签名兼容时恢复。汇总必须检查预期任务全集，不能扫目录把过期或未完成批次拼入结果。清理只允许针对本次run的受控产物，失败不得覆盖已发布目录。

迁移按静态预检 → 合成接口/恢复测试 → 小规模真实试运行 → 科学质量评估 → 全量运行 → 发布验收推进。至少测试非午夜起始、跨日和跨年、不同采样率与仪器、同名台站、稀疏和密集事件、合法无事件块，以及中断/损坏/输入变化后的恢复。具体工程模块与状态见 [06 实现与验收](06_implementation_and_acceptance.md)。

## 8. 官方主源

主源用于确认方法、格式和软件边界；实际运行应固定版本、权重和本项目批准的控制文件。

- [LOC-FLOW 官方仓库](https://github.com/Dal-mzhang/LOC-FLOW)：拾取、关联、绝对及相对定位工作流。
- [PhaseNet 官方仓库](https://github.com/AI4EPS/PhaseNet)：神经网络相位拾取、输入与模型说明。
- [REAL 官方仓库](https://github.com/Dal-mzhang/REAL)：P/S关联与初始定位；Zhang等，2019，doi:10.1785/0220190052。
- [ETH VELEST 官方说明及指南](https://seg.ethz.ch/software/velest.html)：一维速度与震源参数反演；选择只定位模式不等于完成联合模型反演。
- [FDTCC 作者仓库](https://github.com/MinLiu19/FDTCC)：波形互相关差分时间及输入约定。
- [hypoDD 作者官方页及指南](https://www.ldeo.columbia.edu/~felixw/hypoDD.html)：双差重定位方法、程序和版本资料。
