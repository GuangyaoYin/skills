# 文件夹、运行管理与复现规范

## 统一结构

```text
data-locflow/
  README.md
  config/                    # 模板与已冻结项目配置
  profiles/                  # 项目配置规范与独立项目覆盖；不含隐式区域默认
  examples/<case>/            # 显式选择的案例；通用功能不依赖
  schemas/                   # 表结构、字段和格式示例
  scripts/                   # 本次可执行预检与验收工具
  tests/                     # 检查逻辑的合成案例
  docs/                      # 方法、参数和验收规则
  reports/                   # 本次只读审计，不是新的定位计算
  runs/<project>/<run_id>/    # 下列为待实现后端采用的目标结构
    inputs/                  # 清单、元数据快照、只读原数据引用
    config/                  # resolved.json + 软件原生控制文件
    work/
      01_waveforms/<partition>/
      02_picks/<partition>/
      03_real/<partition>/
      04_absolute/<partition>/
      05_dtct/<partition>/
      06_fdtcc/<pair_batch>/
      07_dtcc/<cluster>/
      08_magnitude/<partition>/
      09_uncertainty/<method>/<replicate>/
    products/
      observations/          # picks、关联、互相关、测幅关系表
      catalogs/              # 各阶段目录、主目录及派生视图
      uncertainty/           # 每事件散布、敏感性、试验覆盖
      figures/               # 编号PNG和同名TXT/JSON/TSV
    manifests/               # 输入、阶段、图件和发布清单
    logs/<stage>/<task>.log
    reports/                 # QC、拒绝原因、完整验收与运行总结
    state/                   # 状态与锁；不能替代科研产品
    tmp/                     # 仅本次运行临时文件
```

工作流代码可独立放置；项目原数据与运行目录通过配置指定，不要求任何特定父目录或原工程布局。引用或复制必要的小型控制文件，不直接移动已有科研模块，也不把旧结果目录清空后当成新运行空间。原始波形只读，仪器响应与模型按哈希形成小型快照。案例目录只保留可追溯的参考，不是默认依赖。

`run_id` 建议 `UTC时间_配置短哈希`；日期、时区和哈希均写入 manifest，不靠目录名承载唯一证据。`partition` 为处理分区，研究时段不应写成六个固定月份；分区之间的重叠／合并策略必须明确。

## 阶段状态和断点恢复

状态采用 `pending/running/failed/succeeded/skipped/invalidated`，每个任务记录输入哈希、有效参数、后端可执行文件哈希、适配器版本、开始结束时间、退出码、产物哈希与解析统计。

`succeeded` 必须同时满足：进程退出 0、预期文件可解析、科学门槛与数量闭合通过。仅有 `.done`、旧 `.reloc`、非空日志或子进程启动成功都不算完成。没有地震的时段可记 `succeeded_zero_events` 并附输入覆盖与阈值，不能生成虚构目录；当前 `audit-catalog` 只面向非空发布目录，空目录返回失败。

恢复时重新比较依赖哈希，任何输入、模型、测幅方法或后端变化都失效对应任务及其下游。修改深度色标只重画相关图；修改最终位置至少失效距离相关震级、相应误差、目录与图。缓存的幅值仅在其波形／响应／测量算子／窗口未变且可验证时复用，不能复用旧震源距。

严禁在通用入口运行历史 `rm -rf` 清理命令。每个任务使用独立工作目录，结果先写临时产物、校验通过后原子提交。失败产物与日志保留供排查，重新计算产生新 task 版本；清理只按 run manifest 中已登记、且可再生的 `tmp/` 与工作副本进行。

后台启动、`tee`、分批并行均需等待所有子进程并检查各自退出状态。先完成拾取转换再关联，不因看到部分日文件就提前开始 REAL。日志中的文字“Done”不能覆盖非零退出码。

## 软件和资源

固定 Python 环境、TensorFlow／PhaseNet 权重、ObsPy/TauP、REAL、VELEST、ph2dt/hypoDD、FDTCC、绘图库和编译器版本。至少记录实际执行路径与 SHA256；源码 commit、编译选项、容器镜像摘要按可用性补充。`workflow.env` 的值只是配置线索，必须核对最终生成的原生输入和实际命令。

资源预算明确 CPU 核数、内存、磁盘、GPU、每任务线程数、任务并行数与超时。`任务数 × 每任务线程数` 不超过分配核心预算；FDTCC 按事件对切批而非固定时间窗丢弃跨窗联系。模型／走时表为只读共享输入，任务临时文件独立，禁止并发写同名 `dt.cc`、`final.CNV` 或 `hypoDD.reloc`。

首次完整算量前运行小样本回归，测量每小时波形、每万个事件对、每次扰动的时间和峰值内存，再推算全量资源。某台机器的并发与线程设置不能作为任意机器默认值。

## 版本与成果发布

正式发布版本包括：完整配置和输入清单、所有层级控制文件、主目录与派生视图、事件追溯、质量／误差报告、图件及数据、后端版本、验收 JSON 和可重现命令。

主目录冻结后只读，不直接覆盖。新版本通过独立验收后再原子更新 `current` 指针／registry；旧版本连同原因归档。对照目录、外部参考、试验定位、模板成分分别有明确角色，不能以“最新文件”代替正式入口。

每个项目仅使用自己已验收的发布入口进入正式统计与绘图；新增方法或实验定位在通过对应项目验证前保持独立分支。案例中的正式／实验身份只在该案例内有效，不能成为所有项目的软件选择规则。现有项目入口不会因安装通用框架而被自动替换。
