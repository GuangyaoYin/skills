# 原生公式与检查

用户要求公式为 PowerPoint 内置的可编辑数学对象。分式、矩阵、上下标及其他数学结构都应保留；数学字体可以单独设置，英文正文仍使用 Times New Roman。

## 作者路径

先检查当前演示文稿工具是否明确支持创建和保留原生公式。支持普通富文本、导入/导出 PPTX 或显示趋势线公式，均不足以证明支持通用数学公式。

优先采用当前工具实际支持且验证过的原生公式能力。必要时可以使用 PowerPoint 支持的 OfficeMath/OMML 文件处理路径，但须依据相应格式文档并验证结果；不要凭字符串形似公式就认为已经完成。

当前所查 Presentations 本地 API 文档未提供可直接确认的通用原生公式作者接口。因此本技能不提供一个未经验证的公式生成 API，也不保证仅导出 PPTX 就能满足要求。实际任务有公式时，先在临时副本制作具有代表性的样例，再验证作者路径。没有公式的任务不需要为此中断。

若缺少可行路径或验证条件，明确指出哪些公式无法确认、哪些检查已做及哪些未做；继续完成可完成的内容，不将公式图片、普通文本拼接或未经验证的对象作为合格公式交付。不得默默降级。

## 样例与最终验证

根据实际公式选择样例，例如带上下标的符号、分式、多行方程或矩阵，不为不涉及的结构强加测试。检查：

1. 数学结构、变量、正负号、索引、单位和对齐是否与材料一致。
2. PPTX 中是否存在原生数学对象，而不是仅有图片或普通文本。
3. 在支持公式的 PowerPoint 中打开，能否进入公式编辑、修改结构和保存；没有完成该检查时如实说明。
4. 渲染后的分式、矩阵、上下标及数学字体是否完整、可读、无溢出。
5. 导入、再导出或其他后处理后，原生对象及编辑性是否仍然保留。

包内有数学 XML 只能支持结构判断，不能单独证明 PowerPoint 真实编辑成功或视觉正确。静态检查与实际应用中的编辑验证需要分别记录。

## 包结构检查助手

`scripts/inspect_research_pptx.py` 使用 Python 标准库读取 PPTX，不修改文件。它报告实际页序、原生公式候选对象、非空正文备注、图片/文本/表格数量及声明字体。默认输出不包含备注正文或科研内容。

从本技能目录运行，或将脚本路径解析成绝对路径：

```text
python scripts/inspect_research_pptx.py /path/to/deck.pptx --expected-slides 12 --expected-equations 4 --require-notes
```

上面的数字仅展示命令参数，按实际安排和公式清单替换；不要将其作为默认页数或公式配额。`--expected-equations` 检查候选对象数量至少满足预期。它不能识别所有假公式图片，也不能替代逐一核对数学内容和 PowerPoint 编辑性。`--require-notes` 检查每页存在非空正文备注，不能判定来源或讲述是否充分。

需要保存机器可读检查记录时使用 `--json-out /path/to/check.json`。该记录是工作文件，默认不作为讲稿或正式交付内容。
